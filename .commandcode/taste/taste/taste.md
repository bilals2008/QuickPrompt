# Taste
- Prefers a minimal UI surface: favors removing extra/redundant options and view modes, keeping only the essentials (e.g. pruning a list of views down to just the ones in active use, such as stripping a vault page down to grid-only). Confidence: 0.85
- Dislikes colored borders on cards/UI elements (e.g. the theme accent-colored card outlines); prefers borderless cards with visible borders/dividers removed. Confidence: 0.8
- Dislikes shadows on cards, including hover shadows (e.g. `shadow-sm` / `hover:shadow-md`); prefers completely flat cards with no shadow at all. Confidence: 0.8
- For view/mode switching, prefers a dropdown menu whose items show both an icon and a text name (with the active one marked), over a row of icon-only buttons. Confidence: 0.8
- Writes instructions as short, casual Hinglish (Roman-script Hindi mixed with English), e.g. "shadow hatao yar", "yeh modes ki dropdown bana do like with icon and name ok", "baki modes del karo". Confidence: 0.7
- Prefers no type badges/labels on vault items (e.g. "Note", "Token" pill badges); wants items to show only the icon and title. Confidence: 0.8
- Dislikes unilateral or "random" changes: wants the agent to propose options and reach agreement before removing or replacing existing features/UI (e.g. pushed back repeatedly after alternate vault view modes were deleted without asking, and again when a suggested layout missed the point). Confidence: 0.8
- Wants a "desktop-level" layout for the mini window: dense 2-up card columns side by side rather than a single-column list. Confidence: 0.6
- Wants copying from item cards to be trivially easy — a visible, one-click copy affordance instead of relying on hover to discover it, and the copy action should be present inline in every view including list rows. Confidence: 0.7
- Prefers dense, single-line list rows in the narrow mini window — dislikes tall multi-line rows that waste vertical space (rejected a two-line row layout as worse than the single-line original); wants fewer controls visible per row and secondary actions tucked into an overflow `⋯` menu, keeping only primary affordances (e.g. copy) inline. Confidence: 0.85
- Never uses the full/maximized app window — always works inside the narrow mini window (~360–500px). UI must be designed for that width (e.g. avoid viewport breakpoints like `sm:`/`lg:` that never fire). Confidence: 0.85
- Prefers dead/unused code be deleted rather than left behind — explicitly approves removing orphaned files/components ("agar dead hai aur kisi kaam ka nahi tu del kar do"), so long as any still-used helpers are relocated first. Confidence: 0.8
- Wants multiple view modes/options, not a single one, but each must be polished/"professional" and consistent with the app's existing conventions (e.g. matching HomePage's grid/list toggle + `settingsAPI` persistence) rather than implemented ad hoc. Confidence: 0.8
- Dislikes purple and gray/neutral-gray color families in the UI palette — explicitly "hates purple gray types color"; avoid violet and neutral grays when designing themes or accents. Confidence: 0.8
- Prefers soft, subtly tinted themes over solid/flat or neon ones: surfaces should be gently color-tinted (e.g. warm-shifted browns for a warm theme) with low-saturation muted accents, not solid blocks or high-contrast neon. Confidence: 0.7
- Prefers icon pickers to be a cohesive, purpose-built set where the glyph actually depicts the thing it represents (e.g. real folder-shaped icons in a folder appearance picker) rather than a grab-bag of generic symbols (rocket, leaf, flame, pin) he calls "faltu"/random filler. Confidence: 0.7
- Wants a built-in demo/test toggle to exercise UI states during development (e.g. a demo control simulating an update download so the progress UI can be previewed without real conditions); note he later asked for such a demo button to be removed, so any dev-only demo affordance should stay minimal and easy to delete. Confidence: 0.4
- Prefers additive changes over replacements: when he asks for a new look or feature, he wants everything already implemented to be kept as well ("ab jo tum ny already kiye haan wo bhi rehy but yeh bhi ok"), not swapped out. Confidence: 0.6
- Communicates desired visual styles by pointing to external references (GitHub repos, icon-marketplace/community pages, screenshots) and expects that look reproduced; verify licensing before bundling third-party assets (e.g. Icons8 requires paid/attribution terms, so replicate the style with original assets instead). Confidence: 0.7
- Prefers colorful, multi-tone icons styled like polished commercial icon packs (e.g. Icons8 "Windows 11 Color" folders with a two-tone folder body plus a separately-coloured emblem badge) over monochrome icons tinted from a single `currentColor`. Confidence: 0.55
- Cost-sensitive about assets and tooling: favors free/no-cost sources and pushes back on anything framed as paid ("abey koi paid nahi yeh dekho"), expecting freely available/community alternatives to be used where feasible. Confidence: 0.6
